# Проверка планарности и укладка графа

**Выполнил:** Садилов Егор, ПМИ-2.

## Задание

Задание 6: проверить планарность заданного графа с помощью алгоритма комбинаторной укладки и,
если граф планарен, построить его геометрическую укладку.

Программа читает простой неориентированный граф из файла. Для проверки планарности используется алгоритм Демукрона–Мальгранжа–Пертисэ.
Если граф планарен, программа строит его укладку и определяет порядок ребер вокруг каждой вершины.

Если граф непланарен, в отчете указываются вершины примыкания фрагмента, для которого не нашлось подходящей грани.
Для планарного графа дополнительно строится PNG с прямыми ребрами без пересечений. Координаты вершин вычисляются методом Тутте.

Примеры результата:

![Планарный граф](results/png/planar.png)

![Триангулированный граф из 20 вершин](results/png/triangulated-20.png)

## Структура проекта

- `model` - вершины, ребра, граф и координаты;
- `algorithm` - двусвязные блоки, алгоритм Демукрона и укладка Тутте;
- `io` - чтение входного графа, текстовый отчет и PNG;
- `Main.kt`- запуск основных этапов программы.

## Входной файл

Первая строка содержит:

```text
n m
```

где `n` — число вершин, `m` — число ребер.

Далее идут `m` строк вида:

```text
u v
```

Вершины нумеруются от `1` до `n`.
Петли и повторные ребра не допускаются. Изолированные вершины допускаются.

Пример `examples/planar.txt`:

```text
5 8
1 2
2 3
3 4
4 1
1 5
2 5
3 5
4 5
```

## Как работает комбинаторная укладка

Сначала граф разбивается на двусвязные блоки. Части, которые соединяются только через отдельные вершины, можно укладывать независимо.
Мосты также обрабатываются отдельно.

Для каждого блока с циклами программа выбирает начальный цикл. После его укладки получаются внутренняя и внешняя грани.
Дальше рассматриваются еще не уложенные части графа. Это могут быть отдельные ребра или группы новых вершин,
соединенные с уже построенной частью. Для каждой такой части программа находит вершины, через которые она присоединяется к текущей укладке.

Например, если уже уложен цикл:

```text
1-------2
|       |
|   x   |
|  / \  |
4-------3
```

то часть с вершиной `x` присоединяется через вершины `3` и `4`. Чтобы добавить ее без пересечений, должна существовать грань,
на границе которой находятся все вершины присоединения.

Для каждой части программа вычисляет количество подходящих граней. Если подходящих граней нет, продолжить укладку невозможно, и граф считается непланарным.
Если подходящих граней несколько, программа сначала выбирает часть с минимальным их количеством.
Это позволяет раньше обрабатывать наиболее ограниченные участки графа.

После выбора подходящей грани внутри нее проводится цепь между двумя вершинами присоединения.

Например:

```text
A --- x --- y --- B
```

Эта цепь делит выбранную грань на две новые. После этого программа снова ищет оставшиеся части графа и проверяет, в какие грани их можно добавить.
Процесс продолжается до тех пор, пока все ребра не будут уложены или пока не встретится часть, для которой нет подходящей грани.

Когда все ребра уложены, программа получает порядок ребер вокруг каждой вершины.

Например:

```text
1: 2 5 4
```

означает, что вокруг вершины `1` ребра идут в порядке:

```text
1-2 -> 1-5 -> 1-4
```

Этот порядок сохраняется в отчете.

## Как работает геометрическая укладка

После проверки планарности программа вычисляет координаты вершин.

Каждая связная компонента рисуется отдельно. Для одной вершины или одного ребра координаты задаются сразу.
Для более сложных компонент граф сначала временно дополняется новыми ребрами.

Программа перебирает отсутствующие ребра и добавляет те, которые не нарушают планарность.

Например:

```text
A-------B
|       |
|       |
D-------C
```

может быть временно дополнен диагональю:

```text
A-------B
|  \    |
|    \  |
D-------C
```

Добавление продолжается до тех пор, пока новых ребер добавить уже нельзя.
После этого одна треугольная грань выбирается внешней, а ее вершинам задаются фиксированные координаты.

Например:

```text
        A
       / \
      /   \
     /     \
    B-------C
```

Оставшиеся вершины размещаются методом Тутте. Для каждой внутренней вершины ее координаты должны быть равны среднему координат соседних вершин:

$$
x_v = \frac{1}{\deg(v)} \sum_{u \in N(v)} x_u,
$$

$$
y_v = \frac{1}{\deg(v)} \sum_{u \in N(v)} y_u.
$$

Например, если вершина соединена с тремя точками:

```text
A = (0, 0)
B = (6, 0)
C = (3, 6)
```

то ее координаты будут:

$$
x = \frac{0+6+3}{3}=3,
$$

$$
y = \frac{0+0+6}{3}=2.
$$

То есть:

$$
P=(3,2).
$$

На практике координаты внутренних вершин зависят друг от друга.

Например:

$$
x_4 = \frac{x_1+x_5+x_7}{3},
$$

$$
x_5 = \frac{x_2+x_4+x_6}{3}.
$$

Поэтому программа составляет систему линейных уравнений сразу для всех внутренних вершин.

Для координат `x` получается система:

$$
Ax=b_x,
$$

а для координат `y`:

$$
Ay=b_y.
$$

Обе системы решаются методом Гаусса. После этого становятся известны координаты всех вершин.

После достроения графа метод Тутте позволяет расположить вершины так, чтобы каждая внутренняя вершина находилась в среднем положении между своими соседями. Полученные координаты дают прямолинейную укладку без пересечений.

В итоговом PNG временно добавленные ребра не рисуются. Остаются только ребра исходного графа.

## Пример работы

### Дано

В файле [examples/planar.txt](examples/planar.txt) задан граф из пяти вершин и восьми ребер:

```text
5 8
1 2
2 3
3 4
4 1
1 5
2 5
3 5
4 5
```

### Получилось

Программа признала граф планарным. В [текстовом отчете](results/txt/planar.txt) записаны порядок ребер вокруг вершин и найденные координаты:

```text
Vertices: 5
Edges: 8

Planar: yes

Cyclic edge order:
1: 2 4 5
2: 1 5 3
3: 2 5 4
4: 1 3 5
5: 1 4 3 2

Coordinates:
1: (0.000000, 0.000000)
2: (4.000000, 0.000000)
3: (1.818182, 1.272727)
4: (1.272727, 1.590909)
5: (2.000000, 3.500000)
```

Например, строка `1: 2 4 5` показывает порядок ребер вокруг вершины 1. По найденным координатам построен [рисунок графа](results/png/planar.png).
